[[
由于 曾经犯过严重的逻辑失误[#见下面#]，这里先看一些转义符用例:
  + xml 只有 3个 超符: 『<』『>』『&』
    自嵌套 转义后 变成 『&lt;』『&gt;』『&amp;』
      注意: 转义序列 只含 唯一一个超符 即 转义符『&』，这是正确的设计
  + py 单行单引号字符串字面量内部 只有 2个 超符:『'』『\』
    自嵌套 转义后 变成 『\'』『\\』
    注意:这是糟糕的设计
      不断嵌套，导致数据爆炸:
        再次自嵌套 转义后 变成 『\\\'』『\\\\』
        三次自嵌套 转义后 变成 『\\\\\\\'』『\\\\\\\\』
  + 同样糟糕的时 py的 格式模板字符串:其单行单引号字符串字面量内部 只有 4个 超符:『'』『\』『{』『}』
    自嵌套 转义后 变成 『\'』『\\』『{{』『}}』

现在说说我刚刚犯过的失误:
  起先，注意到 需规避模式 f'{转义符}{转义符:=前一字符}'
  然后，注意到 需规避模式 f'{转义符}{转义符}' #多个转义符共存版
  最后，才注意到 需规避模式 f'{转义符}{超符串首符}'
      #否则 超符的存在 会一直产生更多噪声/垃圾数据
  所以 合理的转义序列 只能是: regex:『{转义符}{普通字符}+』
  同理 合理的超符串 只能是: regex:『{超符}{普通字符}+』

定义:
  本文只考虑 单字符的超符(也包括:转义符是单字符)，只考虑 超符是超符串首符的形式，只考虑 双字符转义序列
  [超符串=[def]=非普通文本，有特别接受，相当于某种指令]
  [超符串首符=[def]=某个超符串的首字符]
  [超符{讨论转义的语境中}=[def]=超符串首符]
  [转义序列=[def]=超符串的一个子类，本文只考虑用于消除所有超符{除了转义符本身的首符} 的 转义序列]
      # 转义序列 的 另一种用途:切换语义{超符<->普通字符}:vim.regex:\m,\M,\v,\V:magic,nomagic,very_magic,very_nomagic
  [转义符 =[def]= 转义序列的首符]
  [转义序列 <: 超符串]
  [转义符 <: 超符]
  [转义符集 <= 超符集 <= 源语言字母表 <= 可显示字符集]
  本该:[普通字符集 <= 源语言字母表 -超符集]
  本该:[字符保留区 =[def]= 源语言字母表 \-\ 超符集 \-\ 普通字符集]
  在只考虑转义的语境中，可将 字符保留区 归入 超符集，或者说:
  [字符保留区 =[def]= {}]
  [普通字符集 =[def]= 源语言字母表 \-\ 超符集]

  [源语言语句 =[def]= [Either 超符串 普通字符]]
  [转义前文本 =[def]= [(超符|普通字符)]]

  本该:[转义后文本 =[def]= [Either 转义序列冃普通文本 普通字符]]
  本该:[解释冫转义序列扌 :: 转义序列 -> Either 超符串 普通文本]
    由此:分成两类:转义序列冃超符串, 转义序列冃普通文本
  !! 本文只考虑 单字符逐个转义，以保证 『片段的转义后文本的串接依然相同』
  =>[解释冫转义序列扌 :: 转义序列 -> Either 超符 普通字符]
  =>[转义后文本 =[def]= [Either 转义序列冃普通字符 普通字符]]
    由此:分成两类:转义序列冃超符, 转义序列冃普通字符

  !! 避免数据爆炸
  [超符串的合理形式 ~ regex'{超符}{普通字符}+']
  =>[转义序列的合理形式 ~ regex'{转义符}{普通字符}+']

  !! 只考虑 双字符转义序列
  =>[转义序列的合理形式 ~ regex'{转义符}{普通字符}']
  !! 保证可以 转义/编码 所有 超符
  =>[len(超符集) <= len(转义符集)*len(普通字符集)]
      毛病在于:不够直观，超符 对应的 普通字符 到底是哪个？
        解决的方案:
          * 要么 引入 一套 形似于 标点符号(超符) 的 字母(普通字符) #见下面:标点符号讠形似字母数字
          * 要么 尽量减少 超符数量，类似于 xml
              最少 只需一个超符，同时也是 转义符

[A := len(源语言字母表)]
[T := len(普通字符集)]
[M := len(超符集)] # 包括:保留区
[E := len(转义符集)]
[A == M+T]
[1 <= E <= M <= E*T == E*(A-M)]
[T >= M/E >= 1]
!! [A == M+T >= M+M/E >= 2]
[A >= 2]

[E == 1]:
    [1 == E <= M <= T == (A-M)]
    [M == 1]:
        [1 == E == M <= T == (A-1)]
    [E := 『~』]:
      『~.』 => 凡符『~』
        手写非标准形式:
        『~(.数字)』 => 凡符串『~』*数字
        『~(:数字)』 => 展开成『~』『.』*数字
      #转义序列 只用于 短途解析，类似 『&gt;』，不嵌套:
      『~字母数字.』 => 超符:标识『字母数字』
      『~[...]』 => 超符串『...』
      『~{xyz:...:xyz}』 => 超符串『...』
          #也许没必要...
          #也许可以稍微复杂点，超符串 类似 整个xml.start_tag『<tag attrs...>』但是 这样 就必须允许某种程度的嵌套:只允许 非括号型的超符，即嵌套深度最多为2
